# Governance

Costura is an open project. Anyone can contribute, and the maintainer list is meant to grow.

## Roles

A contributor opens issues, reviews pull requests, and sends changes to code, tests, or docs.
Anyone can do this. See [CONTRIBUTING.md](CONTRIBUTING.md).

A maintainer reviews and merges pull requests and tags releases. Maintainers share that work.
Each one is listed below and in [.github/CODEOWNERS](.github/CODEOWNERS).

## Decisions

Day-to-day changes land through a pull request. A pull request merges when a maintainer
approves it and no maintainer objects.

A change that binds the next design states the decision and what it costs in the pull
request description.

When maintainers disagree, they discuss it on the issue or pull request. If the
disagreement is still open after that discussion, the maintainers decide by a simple
majority of the people listed below.

## Becoming a maintainer

Sustained contributions in code, review, or docs are the way in. A current maintainer
nominates someone. The nomination stands when no other maintainer objects within 7 days.
The new maintainer is then added to the list below and to
[.github/CODEOWNERS](.github/CODEOWNERS). Turning on a required code-owner review waits
until that file lists more than one reviewer; with a single entry every change waits on
that reviewer.

## Leaving

A maintainer may step down at any time by opening a pull request that removes their name
from this list and from `.github/CODEOWNERS`. A maintainer with no activity in the
repository for 6 months becomes emeritus: the name moves to an emeritus note here, and
review requests stop. An emeritus maintainer returns through the same nomination.

## Conduct and security

[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) is how people are treated in this project.
[SECURITY.md](SECURITY.md) is how to report a vulnerability, through GitHub private
vulnerability reporting. Bugs and support questions use
public issues. There is no separate security mailbox and no private GitHub message channel.
